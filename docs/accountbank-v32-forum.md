# AccountBank v32 — облачный архив по диалогам

## Замысел

Для каждого аккаунта создаётся отдельная приватная форум-группа «Архив
AccountBank». Каждому исходному диалогу соответствует одна тема с читаемым
именем и устойчивой меткой. События изменения и удаления направляются в тему
своего диалога. Локальная зашифрованная база остаётся основным архивом.

Это соответствует [Telegram API для форумов](https://core.telegram.org/api/forum):
группа создаётся с `megagroup|forum`, тема — через
[`messages.createForumTopic`](https://core.telegram.org/method/messages.createForumTopic),
сообщение направляется в неё через `inputReplyToMessage.reply_to_msg_id`.

## Переход с v31

- Существующий вещательный канал сохраняется и доступен через отдельный пункт
  меню «Открыть прежний канал архива».
- Ожидающие отправки события, уже назначенные прежнему каналу, остаются в его
  очереди. Новые события назначаются форуму. Старые отправленные записи не
  копируются повторно, чтобы не создать дубли и не вызвать ограничения API.
- ID форума и соответствие «диалог → тема» сохраняются в зашифрованной
  `archive.ab`. Ключи поиска тем — HMAC, имена диалогов в таблице не лежат
  открытым текстом.
- Создание темы использует постоянный `random_id`, а отправка события —
  постоянный `random_id` записи. После неопределённого результата приложение
  сверяет форум/тему с сервером перед повтором. Поиск темы постраничный.
- Ошибка одной записи откладывает её и не блокирует другие диалоги. Интервал
  `FLOOD_WAIT` сохраняется и после перезапуска. Если тему удалили, для новых попыток создаётся
  новая тема; содержимое удалённой пользователем темы не восстанавливается.

## Ограничения и проверки

- Содержимое облачного архива — обычные сообщения Telegram, а не сквозное
  шифрование. Защищённые сообщения не ставятся в очередь облачного зеркала;
  локальный архив работает отдельно.
- Если создание форум-группы завершилось на сервере, но ответ потерялся,
  приложение ищет группу по устойчивой метке в обычных и архивных диалогах.
  Две полные проверки с интервалом предшествуют повторному созданию. Если
  сервер не позволяет подтвердить результат, очередь остаётся локально и
  повторяется позднее. Проверка результата на реальном аккаунте ещё нужна.
- Если Telegram явно отказывает в создании группы (`400/403`), повторное
  создание останавливается; маркер попытки сохраняется для проверки после
  следующего запуска. Если пользователь закроет тему, события этого диалога
  останутся в локальном архиве и будут ожидать открытия темы. Если тему
  переименовать до восстановления ответа о её создании, сопоставление по
  имени может не сработать; клиент не создаёт слепой дубликат.
- При удалении всей форум-группы автоматическое создание новой не выполняется:
  нужно отдельно решить, что делать с прежними привязками тем и облачными
  сообщениями. Локальные записи продолжают сохраняться.
- Проверить вручную на тестовом аккаунте: два диалога → две темы; две правки
  одного диалога → одна тема; удаление; перезапуск; старый канал v31; удаление
  темы; сетевой сбой; `FLOOD_WAIT`; аккаунты 1/5/10/20/30. Эти проверки не
  заменяются успешной компиляцией.

## Система goal

Старая цель «глубокий аудит и 20–30 одновременно подключённых аккаунтов» всё
ещё имеет статус `blocked`. Система не предоставляет отмену: допускаются
`complete`, `blocked`, `paused`. Завершать старую цель как выполненную нельзя,
поскольку проверка 20–30 реальных аккаунтов не проведена; новая цель в этом
потоке пока не создаётся. Этот документ фиксирует текущую работу отдельно.
