# AccountBank: невыполненные пункты unofficial-features-roadmap.md

Состояние на 2026-10-16. Это отчёт по загруженному плану F1–F15, а не обещание, что тестовая сборка уже реализует весь план. Исходное рабочее дерево содержит незакоммиченные изменения других этапов; их не сбрасывали.

## Что выполнено в этом проходе

- **F13, часть:** в контекстное меню обычного серверного сообщения добавлено «Copy Message ID». Локальные, ephemeral и любые медиа с TTL исключены из действия. Повторный аудит выявил, что первоначальная проверка TTL покрывала фото/видео, но пропускала голосовые; это исправлено в v19. В подсказке с датой серверного сообщения теперь также виден его ID.
- `out-size-os` Release собран, повторная сборка не потребовала работы. Промежуточный пакет v19 был создан и проверен; после выпуска v22 он удалён вместе с прочими пакетами без Data/tdata. Вход, GUI и работа 20–30 аккаунтов не проверены в этом проходе.
- Показ peer ID в профиле уже присутствовал в рабочем коде как отдельная опция (`kOptionShowPeerIdBelowAbout`); повторно не добавлялся.

## Дополнительная работа после v19

- F13: добавлен обработчик `tg://user?id=<число>` для пользователя, уже загруженного в выбранном аккаунте. Произвольный ID без известного access hash не запрашивается у сервера. GUI-переход ещё не проверен.
- F13: показ peer ID в профиле включён по умолчанию для новых настроек; ранее выбранное пользователем значение сохраняется.
- F13: в профиле добавлена причина ограничения из `PeerData::computeUnavailableReason()`, если она доступна. Значение обновляется при `PeerUpdate::UnavailableReason`. GUI ещё не проверен.
- Проверка Qt 6.11.2 показала, что `QLocale::LongFormat` уже включает секунды для `en_US`, `ru_RU` и `th_TH`; подсказка даты использует этот формат. Дополнительная правка для секунд не нужна.
- Пересылка без имени отправителя и без подписи уже доступна в `Ui::FillForwardOptions` (`share_box.cpp`, `window_peer_menu.cpp`); отдельного дублирующего переключателя не добавлял. Если под «без цитаты» имелся в виду другой сценарий, его нужно определить в GUI.
- Подготовлен [технический план защищённого архива](archive-implementation-plan.md). Это не реализация F1: запись сообщений в SQLite ещё не подключена.
- v21 (`-Os`) собран и упакован после этих правок. ZIP: 85 670 410 байт, SHA-256 `c0d7640d6e053c33538f01d74fdaef8c4381c5e33c0ec043261f4ba46fde78f9`. Проверены повторная сборка без работы, ZIP, подпись после распаковки, arm64 и `git diff --check`. GUI, известный/неизвестный `tg://user?id`, ограниченный профиль и 20–30 аккаунтов ещё не проверены.
- v22 (`-Oz`) собран из того же кода и API-конфигурации: ZIP 77 232 145 байт, SHA-256 `9965b1ff93ac51481ec3cd99a02ea6d185ee330fd54af0fd84112f56fa938c81`. Он меньше v21 на 8 438 265 байт (9,85%). ZIP, подпись после распаковки и arm64 прошли; повторная сборка не потребовала работы. Влияние `-Oz` на скорость и память не измерено. v21 сохраняется как `-Os` откат до GUI и 20–30-аккаунтной проверки.
- Старые тестовые пакеты v12–v20, не содержащие Data/tdata, удалены. Сохранены v22, v21 для сравнения и v11 с мигрированными данными. Общая папка профиля и мигрированные данные не изменялись.

## Не реализую предложенным способом

| Пункт | Причина |
| --- | --- |
| F4 Ghost mode | Условия Telegram API прямо запрещают искажение статусов чтения, набора текста и онлайна. Опция per-account не делает это допустимым. |
| F7 Автосохранение одноразовых видео и голосовых | Условия Telegram API прямо запрещают препятствовать исчезновению самоуничтожающегося контента. Не расширяю уже существующий код сохранения TTL-фото. |
| F8 Скрытие спонсируемых сообщений | Условия Telegram API требуют показывать официальные спонсируемые сообщения в каналах; локальное скрытие рендера тоже мешает этой функции. |
| F14 через `NSWindowSharingNone` | Apple называет эту константу устаревшей и прямо не рекомендует её для сокрытия окна от записи экрана. Нельзя выдавать это за надёжную защиту. |

Источники: [Telegram API Terms, пп. 1.4 и 3.3](https://core.telegram.org/api/terms), [Telegram Sponsored Messages](https://core.telegram.org/api/sponsored-messages), [Apple NSWindow.SharingType.none](https://developer.apple.com/documentation/appkit/nswindow/sharingtype-swift.enum/none).

В текущем HEAD **уже есть** автосохранение TTL-фото и просмотренных сторис (коммиты `785b3e4`, `d031e1f`, `8305d44`). Я не добавлял и не расширял эти функции. Код сохранения самоуничтожающегося контента противоречит указанному правилу Telegram API; сборку с ним нельзя считать проверенной на соответствие условиям API. Обычный экспорт **своих** материалов и получение копии от отправителя остаются отдельными допустимыми сценариями.

## Отложено: нужны архитектура, ограничения или GUI-проверка

| Пункт | Что осталось и почему |
| --- | --- |
| F1 SQLite-архив | Предложенная обычная SQLite-БД записывала бы тексты 20–30 аккаунтов без шифрования, тогда как рабочий профиль использует защищённое хранилище. Нужны ключ, шифрование, права файлов, лимит объёма, миграции и тесты восстановления. Не создавал такую БД молча. |
| F2 Anti-recall | Зависит от безопасного F1; удержание удалённых элементов в списке чата затрагивает unread, превью и `getDifference`. Не реализовано. |
| F3 История правок | Зависит от F1 и дедупликации серверных правок. Версии сообщений и их медиа пока не сохраняются. |
| F5 Онлайн-лог | Зависит от F1; нужны сроки хранения и защита сведений о контактах. Не собирался. |
| F6 Лог прочтений | Зависит от F1; данные групп нельзя выдавать за точный список читателей. Не реализовано. |
| F9 Автозагрузка всех чатов | Нужны пределы по диску и трафику, исключение TTL/защищённого контента и тест с 20–30 аккаунтами. Без этих ограничений массовую загрузку не включал. |
| F10 Улучшенный экспорт | `td_export` ранее исключён из минимальной сборки. Для возврата нужны решение о росте бинаря, восстановление точек входа и отдельная проверка хранилища. |
| F11 Бэкап сессий | Копия `tdata` содержит ключи доступа ко всем аккаунтам. Нужны шифрованный формат, проверка восстановления и безопасное место хранения. Скрипт для открытой копии не создавал. |
| F12 Local Premium | Косметика не помогает архиву и противоречит текущему минимальному интерфейсу; не сделана. Серверные лимиты не изменяются. |
| F13 Остальные мелкие функции | Секунды уже есть в длинной подсказке даты; ID сообщения и peer ID добавлены/включены, `tg://user?id` открывает только известных текущему аккаунту пользователей, причина ограничения добавлена в профиль. Обычная пересылка уже позволяет скрыть имя отправителя и подпись. Last seen в списке не сделан. Все новые GUI-пути требуют проверки. |
| F15 Экспорт/импорт архива | Зависит от формата, защиты и тестов F1. Deep link и импорт до этого не добавлялись. |

## Ограничение системы goal

Новая цель через `create_goal` не создалась: в этой ветке уже записана незавершённая старая цель AccountBank со статусом `blocked`. Пометить её `complete` нельзя, потому что работа 20–30 аккаунтов и полный GUI-прогон не подтверждены. Эта системная запись не помешала сборке и подготовке данного отчёта.

## Следующая проверка

Запустить v22 в обычном сеансе macOS с рабочим профилем, затем проверить меню и подсказку ID, отсутствие действия на фото/видео/голосовых с TTL, профиль с причиной ограничения, ссылку `tg://user?id=` на известного и неизвестного пользователя, перезапуск, чаты, уведомления и переключение аккаунтов. Сравнить старт, прокрутку и idle RSS/CPU v22 с v21 сначала на одном, затем на 5/10/20/30 аккаунтах. Не запускать две копии одного профиля одновременно. Без этой проверки пакет остаётся тестовым.
