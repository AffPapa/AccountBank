# Облачный архив: один форум на аккаунт

## Причина дубликатов

`ensureCloudForum()` стирал сохранённые ID и access hash форума, если чат ещё не
был загружен в память при новом запуске. Отсутствие в `peerLoaded()` означает
только пустой локальный кэш, а не отсутствие чата на сервере. Следующее нажатие
«Облачный архив» запускало `createChannel` повторно. Вторая ветка делала то же
после `PEER_ID_INVALID` при отправке записи.

## Исправление

- Сохранённая привязка форума не стирается из-за состояния кэша или ошибки API.
- Если привязки нет, клиент ищет группу с точным идентификатором в названии
  среди обычных и архивированных диалогов перед первым созданием.
- После отправки `createChannel` неопределённый результат восстанавливается
  поиском. Автоматическая вторая попытка создания запрещена: она могла бы
  создать ещё одну группу, когда первый ответ потерялся.
- Поиск больше не принимает любую группу с похожим названием: это мог быть
  архив другого профиля или старая копия.

## Проверка

1. На тестовом аккаунте открыть «Облачный архив», дождаться группы, закрыть
   клиент, запустить снова и открыть архив. Должна открыться та же группа.
2. Нажать пункт несколько раз во время поиска: новая группа не появляется.
3. На чистом тестовом профиле с уже существующей серверной архивной группой
   проверить восстановление по идентификатору, если локальная привязка отсутствует.
4. При ошибке доступа к сохранённой группе клиент должен остановить облачную
   отправку, сохранить привязку и не создавать замену сам.

Существующие дубликаты не удаляются автоматически: в них могут быть записи.
Код не открывает и не изменяет реальный профиль пользователя при сборке.
