## Ограничения, которые нельзя обходить флагом «выключено по умолчанию»

- [Telegram API Terms 1.4, 3.3](https://core.telegram.org/api/terms) прямо запрещают ghost mode (F4), удержание самоуничтожающегося контента (F7) и вмешательство в показ официальных спонсируемых сообщений (F8). Не добавляй их, не поручай обход другому агенту. Существующий код TTL/Stories отдельно обозначай как риск соответствия; не рекламируй тестовый пакет как соответствующий этим условиям.
- Apple называет [`NSWindowSharingNone`](https://developer.apple.com/documentation/appkit/nswindow/sharingtype-swift.enum/none) устаревшим механизмом, непригодным для обещания защиты от захвата экрана. Не реализуй F14 указанным способом и не обещай такой защиты без работающего официально поддерживаемого механизма и реального теста.
- Не создавай обычную SQLite-БД F1 с незашифрованными текстами 20–30 аккаунтов. Сначала спроектируй защиту ключа, шифрование, миграции, права файлов, лимиты диска и восстановление на синтетических данных. Без защищённого F1 не делай F2/F3/F5/F6/F15 поверх открытой БД.
- F11 не должен создавать незашифрованную копию `tdata`. Не запускать две версии, использующие один профиль, одновременно.

## Сборка и пакет

Из корня репозитория:

```sh
cmake --build out-size-oz --config Release --target Telegram -j 8
cmake --build out-size-oz --config Release --target Telegram -j 8
git diff --check
ACCOUNTBANK_BUILD_TREE=out-size-oz tools/package-test-release.command v<N>
```

Выбирай новый свободный номер `v<N>`; v22 уже занята. Упаковщик проверяет подпись и ZIP, а скрипт `Запустить AccountBank.command --verify-only` повторно проверяет их без запуска профиля. ZIP содержит `Contents/` в корне, поэтому для отдельной проверки подписи распаковывай его **внутрь** каталога `AccountBank.app`. Команда конфигурации `out-size-oz` получается из `out-size-os` в `docs/size-reduction-plan.md` заменой четырёх флагов `-Os` на `-Oz`; параметры сравнения и результат записаны там же. Не выводи секреты из CMake cache или generated header.
