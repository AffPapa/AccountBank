# AccountBank: порядок внедрения функций

Основа: `docs/merged-features-plan.md`, проверка исходников 17 октября 2026.
Приоритет продукта — быстрый macOS клиент для 20–30 аккаунтов. Каждый новый
экран и фоновый запрос должен оправдывать память, сеть и сложность. Номера ниже
соответствуют пунктам C1–C6 исходного плана.

## Что уже есть или делается сейчас

- C1/4: календарь перехода по дате уже существовал; добавлен вход из меню чата.
- C1/5: био уже разбирает ссылки и упоминания, но Telegram ограничивает часть
  внешних ссылок; менять это без проверки поведения не нужно.
- C4/33: окно пересылки уже умеет убирать имя отправителя и подпись.
- C5/50: в коде уже есть менеджер загрузок; прежде чем писать новый, проверить
  его доступность в минимальном интерфейсе.
- Текущий пакет изменений: C1/1 секунды, C1/3 переход к первому сообщению,
  C1/9 скрытие подсказок о днях рождения и C2/13 список администрируемых чатов.
  Это локальный список известных клиенту чатов, без нового запроса на каждый
  аккаунт и без серверной папки. Нужен визуальный тест на реальном аккаунте.

## Очерёдность

1. **Основа и замеры.** Зафиксировать размер ZIP, холодный запуск, память и
   число запросов на 1/5/10/20/30 аккаунтах. После каждого изменения сравнивать
   с этой базой. Использовать синтетический `-workdir`; живой профиль не копировать.
2. **C1, навигация и спокойный интерфейс.** После текущего пакета: 2, 6, 8,
   10–12. Пункт 7 — только после проверки конфликтов с macOS/Telegram хоткеями.
   Пункт 5 считать частично готовым.
3. **C2, администрирование.** Проверить список 13, затем 14–21 по одному
   изменению. Для 18 не обещать точность выше данных Telegram. Для 22 сперва
   найти реальный источник статистики и не загружать её фоном.
4. **C3, организация.** 26 и 32 — небольшие настройки. Затем 23, 24, 27–30.
   Пункт 25 делить на безопасные массовые действия и отдельно подтверждаемые
   удаления. Пункт 31 — только после оценки стоимости индекса для 30 аккаунтов.
5. **C4, отправка.** Проверить существующий 33; затем 37, 39, 45, 46, 49.
   После них 34–36, 40–42, 48. Массовое удаление 44 и лимит 43 требуют
   отдельной проверки лимитов API. Пункты 38 и 47 не добавлять автоматически:
   голосовые/стикеры скрыты в минимальном клиенте, а серверную метку `via bot`
   нельзя обещать убрать локальным UI.
6. **C5, файлы.** Проверить существующий 50; затем 51, 55, 56, 57, 58, 59.
   Ускорение 52 мерить на реальной сети и соблюдать лимиты Telegram. Пункты
   53–54 противоречат вырезанному проигрывателю и записи голоса; не возвращать
   эти подсистемы без отдельного решения. Пункт 60 проверять на ограничениях API.
7. **C6, отдельные проекты.** Сначала 68 и 70, затем 63. Пункты 61–62,
   64–67 и 69 требуют отдельной архитектуры, проверки безопасности хранилища
   и пользовательских сценариев. 71–72 опциональны; ИИ-функций здесь нет.
8. **Отдельный трек [Я].** Не смешивать с этими коммитами и не считать его
   функции готовыми по одному описанию. Каждую проверять по коду и тестам;
   в особенности не менять ограничения защищённого контента без отдельного
   решения владельца.

## Условия для каждого пакета

- Один небольшой логический пакет и один коммит; не включать грязные сабмодули.
- Release arm64 компилируется; повторная сборка ничего не пересобирает;
  `git diff --check` проходит.
- Проверка GUI на тестовом аккаунте: вход, перезапуск, список чатов, переписка,
  переключение аккаунтов. Компиляция не равна проверке 30 активных аккаунтов.
- Новая настройка идёт в kv preferences, строки — в конец `lang.strings`.
- Удаление/массовая отправка/экспорт сессий имеют отдельное подтверждение и
  не работают фоном без понятного пользователю статуса.
