# AccountBank: повторный аудит 19 октября 2026

После этого аудита часть пунктов реализована в
`docs/accountbank-v53-archive-scope-index-status.md`. Список ниже фиксирует
состояние до v53 и остаётся исходным планом проверки.

Проверялись изменения AccountBank поверх Telegram Desktop, текущая Release-сборка
для arm64 и тестовый пакет v52. Этот аудит исходников и пакета не заменяет проверку
интерфейса и доставки медиа в работающем аккаунте.

## Подтверждено

- Изменения сообщений попадают в историю только для личных диалогов с людьми;
  группы, каналы, боты и «Избранное» исключены (`data_session.cpp`,
  `updateEditedMessage`). Удаления и исходные снимки сообщений по-прежнему
  записываются из других чатов (`logMessage`, `logDeletedBatch`).
- Компактный список обновляет высоту строк после изменения настройки без
  перезапуска (`dialogs_inner_widget.cpp`). Переключатель непрочитанных также
  пересортировывает загруженные списки всех активных аккаунтов.
- Боковое меню содержит создание группы и канала, ссылку на облачный архив,
  «Избранное» и настройки (`window_main_menu.cpp`).
- Чтение 50 последних событий вынесено в фоновый поток, но фильтрация типа и
  диалога происходит после расшифровки каждой записи. Для редкой категории
  возможен проход вплоть до лимита в 2 млн записей (`loadRecent`).
- Сохранение архива, шифрование и часть запросов SQLite выполняются в потоке
  интерфейса (`enqueue`, `flush`, `currentSnapshot`, `processCloudMirror`).
  Пакетное сохранение ограничивает частоту транзакций, но при большой очереди
  удалений задержка интерфейса остаётся возможной.
- Медиа в v52 хранится как ссылка Telegram, затем пересылается в архивный
  топик. Локальной копии байтов нет. Просроченная ссылка, отсутствие сообщения
  в памяти или запрет сервера приводят к текстовой записи без файла. Это не
  гарантированное сохранение фотографии или видео.
- Лимит архива — 2 млн строк; после его достижения новые события перестают
  сохраняться. Автоматической политики удаления старых записей нет.

## Приоритет улучшений

1. **Надёжность медиа.** На отдельном тестовом профиле проверить фото, видео,
   GIF, голосовое и файл после удаления. Затем добавить ограниченный локальный
   кэш разрешённых вложений с очисткой по размеру и сроку, доставкой в топик
   из локальных байтов и явным статусом «файл сохранён / только ссылка / ошибка».
   Не скачивать весь поток чатов без выбранных пользователем границ.
2. **Политика объёма.** Разделить охват правок и удалений в настройках. При
   желании хранить удаления только из личных диалогов это нужно применять и к
   исходным снимкам, и к обработке удаления, иначе база продолжит расти.
   Старые записи не удалять автоматически при смене настройки.
3. **Задержки архива.** Перенести запись и чтение текущего снимка на одну
   последовательную рабочую очередь. Сохранить строгий порядок
   «сообщение → правка → удаление» и проверять ошибки записи до уничтожения
   сообщения. До изменения измерить p95/p99 задержки на синтетической базе.
4. **Поиск в архиве.** Добавить HMAC-индекс типа и диалога без открытых имён
   чатов в SQLite. Для старых записей предусмотреть фоновую, возобновляемую
   миграцию; индекс только для новых событий оставит старый архив медленным.
5. **Запуск с несколькими аккаунтами.** Измерить время старта и память для
   1/5/10/20/30 тестовых аккаунтов. Пока нет замеров, отключать загрузку
   стикеров, GIF или фоновые аккаунты опасно для функций клиента.
6. **Интерфейс.** После технических изменений проверить узкое окно, ночную
   тему, переключение аккаунтов и длинные подписи медиа. Подпись облачного
   события сейчас обрезается по 1000 символам, поэтому хвост блока «Стало»
   в необычно длинной записи может пропасть.

## Проверки этой ревизии

- `cmake --build out-size-oz --config Release --target Telegram -j 8`:
  успешная повторная проверка, `ninja: no work to do`.
- `git diff --check`: без ошибок.
- `Запустить AccountBank.command --verify-only` в пакете v52: ZIP OK.
- Исполняемый файл Release: Mach-O arm64.

Проверка реального профиля и визуальная проверка не выполнялись: правила
рабочего пространства запрещают автоматическое управление приложением.
